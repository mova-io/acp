# Queued terminal content gate

A source can be archived or deleted after Assess dispatches scan_file/scan_batch jobs. The shared per-file implementation now checks the current tenant/provider/account-or-drive/item lifecycle identity before checksum dedup, prior analysis reuse, source cache reads, downloads, or analysis. Queue payloads preserve Drive account identity as well as Graph drive identity. Stored scan ownership and current inventory binding are authoritative; changed ownership/provider/binding and failed lifecycle reads stop execution before content.

Terminal skips produce a fenced, noncompliant skipped record with no score. Rule traces report NOT_EVALUATED, native manifests report NOT_CHECKED, prior PII findings are cleared, and inventory records the exclusion reason. Ordinary done counting can finalize the work, while final scan and Overview counts exclude lifecycle skips from assessed documents. The original lifecycle ledger and provider operation receipt are preserved. A retained restored/nonterminal state wins over an old terminal inventory projection.

Validation on the independent main base: 156 focused tests passed across queued gate, batch, timeout, result fencing, manifest integrity, deferred Assess, lifecycle override, longest-first dispatch, Overview, pre-draft wiring, credential halt, and cross-thread cancellation tests. New fixtures exercise all three cloud providers, all three terminal statuses, both queued job forms, and same-scan or another-scan operations after dispatch. They prohibit cache, dedup, download and analysis callbacks; verify no PASS/review claims, zero assessed/checked counts, preserved receipts, missing/current identity behavior, failed lookup, stale attempts and PII removal. No live provider or paid model calls were made.

Legacy jobs without a complete namespace do not infer cross-scan identity from filenames; a matching current scan inventory terminal disposition still blocks them. Nonterminal incomplete identities remain eligible under the existing behavior. This check covers jobs not yet reading content; it does not cancel an analysis already in progress when an operation occurs. Newly matching rule candidates and staged scheduled orchestration remain separate work.
